RESOLVED — kept for the lesson, not the question.

The author email in the plugin manifests was changed from a work address to a personal one, but
the work address remained in the CONTENT of 3 historical commits, visible via `git log -p` once
the repo went public. Nothing had been pushed, so a rewrite was still free — that was the last
moment it would be. The cost was that a rewrite changes every SHA, and several claim bodies cited
commits by hash, so those references had to be remapped afterwards.

Deliberately not naming either address here: this claim originally quoted the work address, and the
filter-branch pass that purged that string rewrote THIS SENTENCE too — leaving the body asserting
that the new personal address was the one leaking. A blanket string rewrite edits text ABOUT the
string as readily as the string itself, so prose discussing a purged secret should describe it
rather than quote it. Corrected by hand afterwards.
