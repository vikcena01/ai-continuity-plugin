Capture writes git commits autonomously; pushing them is an outbound action the user did not ask for, so continuity commits and stops there (src/core/git.ts has commit/log/revert and no push). The cost — teammates pulling stale state — is paid down by reporting the number of captured commits not on the upstream in the resume header, and staying silent when there is no upstream. If a future session is tempted to 'just auto-push to fix rk4': that was considered and deliberately not done.
