src/core/git.ts reads user.name and user.email and substitutes `continuity <continuity@local>` ONLY when git has neither configured. The fallback still matters — capture must work in a repo with no identity at all — but it must never override a configured one. Do not restore the unconditional form; the original comment ('forced inline so it works with no global git config') described a fallback requirement and was mis-implemented as an override. Verified functionally: a tool-written capture commit now authors as the configured user.
