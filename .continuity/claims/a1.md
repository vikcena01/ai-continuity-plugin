reason: >-
  The resume projection filters on status, so a status default set in more than
  one place means some capture paths produce claims that are written to disk but
  never surface — the worst failure mode for a state layer.
---

Every write path must go through Store.record and let defaultStatusFor(type) choose the initial status: question/risk/milestone/next_action → open, rejected_alternative → rejected, mission → active, everything else → accepted. This exists because two paths disagreed — record_open hardcoded 'open' while capture hardcoded 'accepted' — and renderResumeContext only surfaces question/risk when they are 'open', so every AUTONOMOUSLY captured risk was silently missing from the resume context (rk6). Any new write path that hardcodes a status reintroduces that class of bug.
