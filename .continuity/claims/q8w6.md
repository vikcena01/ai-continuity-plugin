Cowork DOES support plugins — they bundle MCP connectors, skills, slash commands, hooks and sub-agents, installed from the Plugins settings page, and claude.com/plugins is titled 'Plugins for Claude Code and Cowork'. So it is a legitimate option on the submission form. But nothing here has been tested there, and three dependencies could each break it:
  1. We ship a LOCAL stdio MCP server, not HTTPS. Cowork's docs say any MCP server reachable over HTTPS works, while LOCAL servers install from Settings > Developer 'when enabled by the admin' — so ours may be admin-gated rather than working out of the box.
  2. It needs `node` on the device to run dist/mcp.js. Fine in a terminal; unverified in Cowork's runtime.
  3. Repo mode needs a project cwd and a git repo, and Cowork may have neither. That is exactly the case d6 added central mode for, but central mode has never been exercised in Cowork either.

None are known failures — all are unknowns. Recommendation given: declare Claude Code ONLY on the submission, since that is what the 69 assertions and every hook were validated against. To claim Cowork honestly, install it there first and confirm three things: the MCP tools appear, the SessionStart hook injects state, and a capture round-trips to disk. Cannot be tested from a terminal session — it needs the Cowork app. Test BEFORE claiming it: per c6vg, approval pins a commit SHA, so a correction afterwards cannot come from a force-push.

Sources: support.claude.com/en/articles/13837440-use-plugins-in-claude and claude.com/docs/cowork/3p/extensions
